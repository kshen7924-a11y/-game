## 一、全局美术制作硬性规范

| 规范项 | 要求标准 |
| :--- | :--- |
| **文件格式** | 透明素材统一导出 **PNG-32（RGBA，无预乘黑边）** 或无损 WebP；全屏背景/岩壁底图使用 PNG（或高质量 WebP） |
| **色彩空间** | sRGB（8-bit/channel） |
| **统一主光源** | **左上方 45° 自然日光**（受光面偏暖白/粉笔灰，背光面与岩壁投影偏冷青灰 `rgba(30, 58, 72, 0.44)`） |
| **勾线规范** | 角色与道具深墨外轮廓 `#141820`，4× 导出稿建议线宽 **3–5 px**；内部结构线 **1.5–2.5 px**；避免模糊羽化黑边 |
| **画布留白与裁切** | 角色部件、岩点、道具均保持透明底，四周预留 **8–12% 安全留白**（防止旋转抗锯齿裁切） |
| **镜像复用规则** | 人物右侧四肢（`RightUpperArm`/`RightForearm`/`RightThigh`/`RightCalf`/`RightHand`/`RightFoot`）若未单独出图，引擎会自动水平镜像左侧部件；需要左右非对称装备细节时再单独提供右侧贴图 |
| **骨骼方向约定** | 所有**骨骼驱动四肢部件**（大臂/小臂/大腿/小腿）必须**垂直朝下绘制**：起点关节（肩/肘/髋/膝）位于画布垂直 **14%** 处，终点关节位于 **86%** 处 |
| **全局文件命名规范** | 全部采用**全小写 ASCII + 短横线（kebab-case）**，禁止中文、空格及大写字母（避免跨平台/CDN 大小写敏感错误）：<br>• 角色背面立绘：`char-preview-<skinId>-<gender>.png`<br>• 角色局内部件：`char-<skinId>-<limb-kebab>[ -<gender> ].png`<br>• 公共岩壁场景：`wall-<packId>-<layer>.png`<br>• 单关覆写场景：`route-<routeId>-wall-<layer>.png`<br>• 语义岩点：`hold-<packId>-<holdKey>.png` / `hold-overlay-<overlayKey>.png` / `hold-special-<specialKey>.png`<br>• 世界道具：`prop-<prop-kebab>.png`<br>• 线路徽章：`badge-<routeId>.png`<br>• UI 组件：`ui-<group>-<key>.png`<br>• 气象/反馈特效：`vfx-<effect-kebab>.png` |

### 7.3 四大模块硬性制作规范（红线标准）

#### A. 专属岩壁规范（`startLedge` + `climbingWall`）
1. **起攀站立面校准**：`startLedge` 中脚踩平台水平面固定位于画布纵向 **`Y = 85.5%`**（若山脚造型有微调，必须在校准表中提交实际 `startShelfSurfaceRatioY`）；**顶部 0%–18%** 必须为纯连续岩壁纹理（禁止画天空、树冠或孤立杂物），供引擎自动透明羽化融进主岩壁。
2. **垂直无缝平铺红线**：`climbingWall` 顶部 16% 与底部 16% 必须满足**色调、明度、裂隙密度与斜纹走向完全一致**（引擎会取底部 16% 平滑叠加到顶部生成无缝循环瓦片）；画面正中禁止放置过于醒目的孤立奇石或红斑，避免在 100m–145m 长线中出现“贴图重复感”。
3. **HUD 边缘构图友好**：游戏交互按钮已全部收纳至屏幕左右最外侧边缘，中央 75% 区域为纯粹的攀爬主视觉；岩壁左右 12% 边缘可适度压暗 5%–10% 增加纵深感，同时提升左右边缘图标的可读性。

#### B. 专属岩点规范（纯美术读线 + 100% 锚点锁定）
1. **严格锁定物理接触锚点**：每关重新设计的 10 张岩点**必须 1:1 对齐 `HOLD_SPRITE_SPECS` 标准接触锚点**（详见第四章 4.1 表：`jug (0.56,0.36)`、`crimp (0.50,0.49)`、`pinch (0.51,0.46)`、`horn (0.61,0.44)`、`sloper (0.50,0.44)`、`undercling (0.52,0.44)`、`ledge (0.54,0.42)`、`sidepull (0.48,0.48)`、`pocket (0.52,0.44)`、`crack (0.50,0.50)`），确保不改代码即可让手掌/鞋尖严丝合缝贴合抓握棱线。
2. **自然“长在岩壁上”的融合度**：每张岩点四周须自带柔和的**本关同色系根部咬合阴影（Ambient Collar）**，边缘自然羽化透明；严禁生硬白边、黑框或“像贴纸一样浮在岩壁上”。
3. **无 UI 提示下的纯美术语义表达**：
   - `jug` / `ledge`：顶缘宽厚、受光面饱满，传达“高摩擦/可歇脚”；
   - `crimp`：极细硬亮棱线，传达“仅容指尖扣抓”；
   - `sidepull`：竖直侧棱，一侧受光、另一侧深凹暗槽（引擎在右侧拉时自动水平镜像 `flipX`）；
   - `undercling`：上方圆滑无抓点、底部内凹形成清晰反扣暗唇；
   - `sloper`：圆润外倾磨光面、无锐利扣边；
   - `pocket` / `crack`：深邃内凹指洞与 45° 斜裂隙阴影，一眼辨明塞手/打钉位置。
4. **统一受光**：所有岩点保持**左上 45° 受光**（运行时随机倾角限制在 `±21°` 以内，不会上下颠倒）。

#### C. 专属山顶造型规范（`summitNear`）
1. **紧扣关卡名称的标志性山顶雕塑**：每关顶峰不能只是普通平石头，必须将**关卡名称的意象实体化为极具辨识度的顶峰岩体造型**（详见 7.4 表，如天鹅展翼缓弧脊、白马飞檐雪脊、皇家石拱门冠、悬空石英飞檐、蛇脊弧顶、月下砂岩孤柱、魔鬼塔平顶六棱柱冠、盛放花岗岩莲瓣塔尖、艾格冰檐北壁脊、马特洪标志金字塔锋尖、黎明巨壁金色绝巅）。
2. **站立点与衔接红线**：
   - 顶峰站立平脊必须位于画布纵向 **`Y = 30%–45%`**、横向 **`X = 42%–58%`** 区间内，并准确标注归一化坐标 `(summitStandingRatioX, summitStandingRatioY)`，保证登顶瞬间角色双脚稳立峰顶；
   - **底部 82%–100%（下 18%）**必须为连续实岩，色调与纹理直接对接本关 `climbingWall`，供引擎平滑羽化；
   - **顶部 0%–4%** 天空色彩均匀平滑，同步提供 16 进制纯色值 `summitSkyTopColor`，用于超长全面屏向上无限延展无断层。

#### D. 极致浪漫偏写实完攀大场景规范（`wideEnding`）
1. **艺术品质目标**：作为玩家历经坠落、读线与极限攀爬后的**最高情感奖赏**，画面须达到**壁纸级极致浪漫偏写实插画标准**——饱满的氛围光影（晨曦金光、晚霞瑰丽云海、银河银月、高山雪雾旗云）、丰富的远中近景空间纵深与诗意孤独感。
2. **与 `summitNear` 的空间连续性**：
   - `wideEnding` 必须与 `summitNear` **共享同一个核心峰顶造型与地标朝向**（例如峰尖倾向、缺口方位、光源方向完全一致）；
   - 美术须标注该共享地标在 `wideEnding` 中的归一化中心点 `(wideFocalX, wideFocalY)`（推荐落在 `X: 0.46–0.56, Y: 0.24–0.40`）。引擎的连续光学拉远镜头会将 2.5D 实时世界峰顶与 `wideEnding` 的 `(wideFocalX, wideFocalY)` **亚像素锁定在同一屏幕坐标并保持完全一致的对数拉远速率**，同时复用 `vfx.weatherFrontCloud` / `vfx.mistVeil` 轻薄高空流云与 `vfx.sunShaft` 体积光完成自然过渡（无需额外新增登顶贴图）。
3. **三幕式完攀演出 & 一图三用构图安全带（CRITICAL）**：
   同一张 `wideEnding` 将被用于 **① 全屏登顶拉远全景与「欣赏全景」沉浸模式、② 完攀三幕式叙事底图、③ 关卡详情弹窗顶部横幅**，构图须严守以下纵向分区：
   - **`0% – 20%`（苍穹呼吸带）**：纯净浪漫天空、霞光、星月或远云，无杂乱高对比硬块，给屏幕顶部留出空灵呼吸感；
   - **`22% – 48%`（黄金主峰视觉带）**：**关卡核心山峰全貌、最华丽的光照受光面与浪漫天际线必须落在此区域内**（保证在关卡详情弹窗横幅裁剪、第三幕弹窗背景与全屏全景中主峰永不被裁切）；
   - **`52% – 88%`（浪漫云海/深谷叙事承托带）**：云海、薄雾峡谷、山麓针叶林海、暮色雪谷等**较低频、柔和明暗区**，用以优雅承托第一幕「现实首攀传奇人物介绍」、第二幕「攀登评级与唯美诗句」以及第三幕精简徽章卡片，确保浅色文字无需厚重黑底即可清晰阅读；
   - **`88% – 100%`（底部安全收口带）**：沉稳深色山谷或厚重暗云，兼容手机底部 Safe-Area 手势条与右下角「欣赏全景 / 轨迹回放」浮钮。
4. **禁止事项**：画面中**禁止绘制任何文字、水印、UI 边框或显眼大比例登山者人物**（登山者由引擎独立渲染，避免双人重影或比例穿帮）。

### 7.5 单关交付必须附带的 `ArtPackMetrics` 校准表模板

美术每交付一关的 4 张大场景（`start` / `wall` / `summit-near` / `wide-ending`），须同步填写以下校准参数交给程序直接录入，确保 1:1 严丝合缝零跳变：

```json
{
  "routeId": "master-3",
  "startShelfSurfaceRatioY": 0.855,
  "summitStandingRatioX": 0.50,
  "summitStandingRatioY": 0.36,
  "wideFocalX": 0.50,
  "wideFocalY": 0.33,
  "wideDissolveStartScale": 1.34,
  "summitSkyTopColor": "#1A2246",
  "fallbackWallColor": "#9C8472",
  "plinthShadowColor": "#3C2D28"
}
```

| 参数字段 | 含义与测量方式 | 推荐安全范围 |
| :--- | :--- | :--- |
| `startShelfSurfaceRatioY` | `start.png` 中人物双脚踩踏的水平岩台表面纵向比例（`0` = 图顶，`1` = 图底） | `0.82 – 0.88`（默认 `0.855`） |
| `summitStandingRatioX` | `summit-near.png` 中人物登顶站立点的横向比例（`0` = 图左，`1` = 图右） | `0.42 – 0.58`（建议 `0.50`） |
| `summitStandingRatioY` | `summit-near.png` 中峰顶站立岩脊表面的纵向比例 | `0.30 – 0.45` |
| `wideFocalX` / `wideFocalY` | `wide-ending.png` 中与 `summit-near` 共享的核心峰顶地标中心坐标 | `X: 0.45–0.56` / `Y: 0.26–0.42` |
| `wideDissolveStartScale` | 登顶瞬间由 `summit-near` 叠化至 `wide-ending` 时的初始放大倍率 | `1.28 – 1.38` |
| `summitSkyTopColor` | `summit-near.png` 最顶边 `Y = 0` 处天空吸管纯色值（用于超长屏顶部无缝延展） | 6 位 HEX 色值 |
| `fallbackWallColor` / `plinthShadowColor` | 贴图异步解码前的岩壁过渡底色 & 起点底座压暗色 | 6 位 HEX 色值 |

### 10.3 交付前 13 项必检清单
1. **透明边缘无白边/黑边杂色**：所有 PNG 在浅色与深色岩壁底图上均干净无毛边。
2. **角色设定效果图背面站立统一**：4 张背面站立效果图保持同一脚底地平线、同一缩放比例与左上 45° 受光，在手机端左右分栏下头部与鞋底均不被裁切。
3. **四肢垂直朝下 + 14%/86% 关节对齐**：检验肘/膝大幅弯曲时无错位、无露白。
4. **岩点锚点对准抓握面**：11 关所有专属岩点的手掌/脚尖落点刚好扣在 `HOLD_SPRITE_SPECS` 的 `anchorX/anchorY` 受力棱线上。
5. **纯美术读线可用性校验**：关闭所有颜色圈与箭头后（模拟中级/大师级与路书模式），玩家仅凭岩点造型与光影就能分辨大抓点、薄小边、侧拉、反扣与裂缝。
6. **主岩壁上下无缝拼接**：上下叠放两张单关 `climbingWall` 检查接缝完全不可见，长线路无突兀重复斑块。
7. **专属山顶造型与主壁无缝融合**：检查 `summitNear` 下 18% 与 `climbingWall` 色调/肌理无断层，且站立点 `(summitStandingRatioX, Y)` 坐标精准。
8. **完攀大场景极致浪漫感与三幕安全带校验**：
   - `wideEnding` 与 `summitNear` 共享峰顶地标与光影朝向，叠化拉远零跳变；
   - 黄金主峰位于纵向 `22%–48%`，一图三用（全屏全景/完攀三幕/关卡详情横幅）均不裁切主峰；
   - `52%–88%` 区域明暗柔和，承托第一幕传奇首攀者与第二幕唯美诗句清晰易读；
   - 「欣赏全景」纯观景模式下无任何文字、水印或预画人物穿帮。
9. **徽章轮廓清晰可缩读**：11 枚 `512×512` 徽章在 3 秒「岩间静谧」全屏过场大图下工艺精致，缩小至 `44×44 px`（列表）与 `56×56 px`（徽章墙）时仍清晰辨识。
10. **UI 纸纹与舞台底图低干扰**：`parchmentTexture` 与 `characterStageBackdrop` 不抢前景文字或人物轮廓对比度（满足 WCAG AA 可读性）。
11. **VFX 粒子风格统一**：雪片、碎石、冰锥、风痕与路书复盘红点/黄区叠加在单关岩壁上均具备高清晰度。
12. **单关 `ArtPackMetrics` 同步交付**：每关交付目录内均附带完整的 `metrics.json` 校准参数。
13. **全局光照统一**：每关内部的岩壁、10 类专属岩点、角色、道具与近顶山体共享左上 45° 主光，避免“贴纸感”。

### 10.4 Codex / 自动化美术接入工程红线（必读防坑）
当由 Codex 或脚本批量生成/导入资产并挂载到仓库时，必须同时遵守以下 4 条工程约束，避免出现生产环境 404、双层染色发灰或山顶遮挡：

1. **禁止硬编码 `/src/...` 裸字符串路径（Vite 生产构建红线）**：
   - 凡放在 `src/visual/...` 下的 PNG/WebP 资源，必须通过 TypeScript **静态 ES `import`（或 `import.meta.glob`）** 引入后再写入 `AssetRegistry`；严禁使用 `'/src/visual/...'` 字符串（否则 `npm run build` 打包后图片 404）。若使用裸字符串路径，则文件必须放进 `public/assets/...`。
2. **接入单关全彩专属贴图时，关闭程序二次染色与程序山顶覆盖**：
   - `src/visual/artPackAssets.ts` 当前在检测到 `routeTheme` 时，会对继承自公共地貌包的 `startLedge`/`climbingWall`/`holds` 执行 `buildRouteThemedWallTile` / `buildRouteThemedHoldCanvas` 占位染色；`src/visual/scenePresentation.ts` 当前在 `routeTheme` 存在时优先渲染程序雕塑山顶 `drawRouteNearSummitVista`。
   - **当 Codex 为某关注入了专属全彩 `routeOverrides[routeId].walls.startLedge / climbingWall / summitNear` 或 `routeOverrides[routeId].holds[key]` 时，必须在接入层判断该槽位是否已由 `routeOverrides[routeId]` 显式提供**：已提供专属贴图则直接渲染原始全彩贴图（跳过二次程序着色，并用 `summitNear` 贴图替代程序山顶），未提供才回退程序占位。
3. **只读保护核心玩法目录**：
   - 美术接入严禁修改 `src/game/*`（物理、IK、耐力、坠落 `ropeCatch`、关卡生成、音频逻辑），也不得修改 `HOLD_SPRITE_SPECS` 碰撞锚点与 `CHARACTER_RIG_METRICS` 骨骼尺寸。统一新建集中注册模块（如 `src/visual/generatedArtManifest.ts`）并在入口调用 `AssetRegistry.patchManifest(...)`。
4. **接入后必跑校验**：
   - 每次分批生成与挂载完成后，必须执行 `npm run lint`（`tsc --noEmit`）与 `npm run build` 确认零类型错误、零缺失导入、所有静态图片正确打入 `dist/`。
